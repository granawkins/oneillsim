# Simulation loading performance

The legacy simulation is served directly; these changes do not require a Next.js build.

- Skybox faces use 1024 x 1024, quality-85 WebP, with a 12-character SHA-256 fingerprint in each filename. All six faces total 87,822 bytes versus 8,906,515 bytes for the original 2048px PNGs. Originals remain available for future re-encoding. Face order/orientation is unchanged.
- Every distinct model used by the saved world starts loading together immediately after the world GET, before expensive circulation/placement/procedural construction. OBJ and MTL requests run concurrently; all textures must complete before a prototype is ready. The preload caches prototypes without making discarded instance clones. Saved placement order, IDs, compatible material pools, retries and borrowed-resource ownership remain unchanged. Unused editor/library models still load on demand.
- The current 1,573-record scene uses 200 distinct model files. The cold GET-only benchmark verifies all 200 requests start within one second of one another, one download per model and all 1,849 placed texture-map references ready. Increase the test's resource timing buffer: the browser default silently drops entries from a scene this large. The measured encoded scene-asset transfer was 2,445,136 bytes; full readiness additionally includes CPU geometry/collision construction and GPU warm-up, and varies with shared-host load.
- The residential capacity planner stops after its first conflict-free stair-core candidate instead of scanning the remaining unused candidates. Actual before/after plan JSON was checked for exact equality; floors, stairs, parks and saved records are unchanged.
- The habitat renders before world loading finishes. Input/editing and console saves are disabled until readiness. Rotation begins only once ready; capture mode remains fixed.
- The custom static server gzips HTML, CSS, JS, JSON, OBJ, MTL, and SVG responses above 1KB when accepted. Images are not gzipped. Negotiation respects q=0 and validators vary by encoding.
- Fingerprinted skyboxes cache for a year with `immutable`. Unversioned files use ETag revalidation (`max-age=0, must-revalidate`) so code/model edits remain immediately visible but unchanged responses can return 304. World JSON remains `no-store` and never returns 304.
- Compression is scoped to the app's custom static routes; no shared Nginx configuration changes are needed.

Tests: `node --test tests/loading-performance.test.js tests/street-kit-loading.browser.test.js tests/asset-startup.browser.test.js tests/upfront-preload.browser.test.js`. Optional `BASELINE_LOADER`, `BASELINE_MAIN` and `BASELINE_RESIDENTIAL` point to exact prior source snapshots for isolated browser before/after measurements; fixtures intercept only GET responses, never production files/world data.
Browser tests use a read-only live world and a separate browser-intercepted GET fixture for delayed model loading. They never PUT to the world endpoint. The intentionally unauthenticated world-save endpoint is unchanged.
